# 物化视图转换方案 - 执行指南

## 项目概述
本方案旨在将现有的10个`market_ohlcv_*`普通聚合视图转换为TimescaleDB连续聚合物化视图，以提升查询性能和系统效率。

## 当前架构分析
- **现有架构**: 10个普通视图作为物化视图的包装器，每次查询都需要实时计算
- **目标架构**: 直接使用TimescaleDB连续聚合物化视图，提供预计算数据
- **数据保留**: 根据时间粒度设置不同的数据保留策略

## 转换步骤

### 第一阶段：准备和备份
1. **执行备份脚本**
   ```bash
   psql -d your_database -f dbscripts/convert_views_to_materialized_backup.sql
   ```
   - 创建视图定义备份表
   - 备份数据样本
   - 验证数据完整性

2. **验证备份结果**
   - 检查`backup_view_definitions`表
   - 确认10个视图定义已备份
   - 验证数据样本表创建成功

### 第二阶段：转换执行
3. **执行主转换脚本**
   ```bash
   psql -d your_database -f dbscripts/convert_views_to_materialized_main.sql
   ```
   - 创建10个连续聚合物化视图
   - 设置自动刷新策略
   - 创建性能优化索引

4. **执行数据迁移脚本**
   ```bash
   psql -d your_database -f dbscripts/convert_views_to_materialized_migration.sql
   ```
   - 创建过渡视图保持兼容性
   - 初始化物化视图数据
   - 验证数据一致性

### 第三阶段：验证和优化
5. **等待数据填充**
   - 等待30分钟让连续聚合策略完成数据填充
   - 监控物化视图刷新状态

6. **执行性能测试**
   ```bash
   psql -d your_database -f dbscripts/convert_views_to_materialized_performance.sql
   ```
   - 对比转换前后性能
   - 分析系统资源使用
   - 获取优化建议

### 索引策略
每个物化视图创建两个索引：
- `(bucket DESC)` - 时间范围查询优化
- `(coin_id, bucket DESC)` - 币种和时间联合查询优化
